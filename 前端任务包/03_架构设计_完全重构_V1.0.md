- 编制：工程智拓 @pm ｜ 2026-09-14 ｜ 依据：01 需求 D-3、开发规程 §4/§5（S-2 POC、S-4 顺序）、S-1 契约

## 1. 为什么是这套架构（结论先行）

四项硬要求：①桌面工控机交付 ②真几何不能只渲染面片（16(2)）③≥10Hz 轴联动 ④碰撞必须几何级判定。

| 候选 | 判 | 原因 |
|---|---|---|
| 纯浏览器栈（three.js + WASM） | ✗ | 工控机离线部署弱、非桌面交付形态、WASM 几何能力浅 |
| PyQt+PyOpenGL 自绘 | ✗ | 渲染底座从零造，成本高效果差 |
| Qt3D | ✗ | 生态萎缩，显示网格管线不成熟 |
| 收费 SDK（HOOPS/Hosm） | ✗ 本期 | 许可成本未询价，违反 D-8 |
| **OCC 内核 + PySide6 外壳 + 内嵌 Web 视图（本地桥传显示网格）** | ✅ | 真 B-Rep 校验+成熟渲染底座+团队 Python 栈 |

## 2. 进程与数据流

```
┌─────────────────────────────────────────────────┐
│ PySide6 桌面外壳（工作台 UI：步骤条/树/列表/日志）  │
│   ├─ QWebEngineView ── 三维视口（three.js 渲染）   │
│   └─ QWebChannel ⇄ 本地 WS ── 双向桥（bridge.py） │
├─────────────────────────────────────────────────┤
│ core/（纯 Python，无 GUI 依赖，可单测）            │
│   config/      参数体系（轴/行程/零点/比例/方向）   │
│   kinematics/   串联移动副+回转副正解/解析逆解、坐标变换│
│   geometry/    OCC 导入/装配树/B-Rep校验/tessellation│
│   collision.py 碰撞三态（OCC 精判，FCL 备选）      │
│   path.py      路径生成+行程/可达性校核            │
│   project.py   工程文件 JSON 读写（带版本号）      │
├─────────────────────────────────────────────────┤
│ comm/（独立于 core）                            │
│ opcua_client/  asyncua 客户端包（七件）         │
│ simulator.py   按 S-1 点表自建 OPC UA Server    │
│ plc_nodes.py   镜像节点树（按点表建）           │
│ plc_logic.py   握手状态机＋装载/启动/异常注入   │
│ virtual_motion.py 梯形速度规划的虚拟轴运动      │
└─────────────────────────────────────────────────┘
```

## 3. 模块职责与接口签名（骨架，ZCode 照签名填）

| 模块 | 关键函数 | 签名（定死） |
|---|---|---|
| geometry/ | 导入 | `import_model(path:str)->Assembly`（含 `is_brep:bool, tree:[AssemblyNode], stats:{parts,tris,load_ms}`） |
| geometry/ | 显示网格 | `tessellate(assembly, deflection:float)->list[MeshPart{id,name,vertices:nx3 float32,tris:nx3 uint32,face_map:nx1 int32}]`（face_map=三角形→B-Rep 面 ID 映射，T06 取真值法向的唯一依据） |
| geometry/ | 桥载荷 | `encode_mesh_parts(parts:list[MeshPart])->list[dict]`（序列化为桥 `mesh.load` 载荷：顶点 Float32 小端＋索引 Uint32 小端→base64；**每部件只出 `id`／`name`／`vertices`／`tris`／`n_vertices`／`n_tris` 六键**——⛔ `face_map`／`face_index` **一律不下发前端**，04 §7.2-G14 ①「前端只做显示」的落点）⚠️ **2026-09-16 T05 收单后补登**：本函数 T05 卡步骤 5 明列、交付已实现，而 §3 表**此前漏登**（与 kinematics 的 `raw_to_eng`／坐标变换同型缺口） |
| geometry/ | 取点／面心 | `face_point_from_tri(parts,mesh_id,face_id,u,v)->FacePoint` 与 `face_center(parts,mesh_id,face_id)->FacePoint`（**T06 已落码**，落新增件 `face_point.py`）：由拾取三角形的重心坐标换算 B-Rep 面上的**真实 3D 点**，**法向从 B-Rep 面真值取**——经 `MeshPart.face_index[face_id]` 拿活 `TopoDS_Face`、`BRep_Tool.Surface(face)` → `GeomLProp_SLProps`，⛔ **不是三角形法向**（圆柱侧面上两者实测差 2.318°，弦高偏差）。⚠️ 本机 pythonocc-core **7.9.3** 实测：`GeomLProp_SLProps` 收 `Geom_Surface` **句柄**、不是 adaptor；OCC 符号是**模块级小写函数** `breptools`／`topods`，CamelCase 的 `BRepTools`／`TopoDS` **不存在**；`OCC.__init__.VERSION` 硬写 7.9.0 是陷阱，⛔ 不得据此写版本号。<br>**（2026-09-16 T06 收单后补登；照录留痕——原冻结签名写 `face_point_from_tri(mesh_id,face_id,u,v)->Point`／`face_center(mesh_id,face_id)->Point`，与交付实测不符，按 §3 V1.5-③ 同口径回填）**：**① 新增显式首参 `parts:list[MeshPart]`**——原签名**没有任何几何来源**（顶点／三角形／`face_map`／`face_index` 全在 `tessellate` 产出的 `list[MeshPart]` 里，按字面无法实现），取**损害最小**的第三条路：把数据源作显式首参、零硬编码、调用方（壳）持有 `parts` 即可（**同 T04 `fk(joint_values,model)` 显式传参先例**）；**② 返回类型 `Point`→`FacePoint`**——`core.kinematics.Point` 已是裸 `(x,y,z)` 元组别名，同名异义会重蹈 `Frame`／`CoordFrame` 覆辙（§3 消歧注）。**③ 登记两个数据类**：`FacePoint`（**frozen** dataclass：`pos_mm:tuple[float,float,float]`＝模型坐标系真实 3D 点、`normal:tuple[float,float,float]`＝单位真法向、`source_face:int`＝所属 B-Rep 面 id）；`Waypoint`（dataclass：`id:int` 稳定不重排、`name:str` 默认 P1／P2… 可手改、`pos_mm`／`normal` 取自 `FacePoint`、`source_face:int`；**T07 `gen_path` 的输入**，见本节 path.py 行；**GUI-free**——无 PySide6 依赖，故落 core 而非 app，core 不得 import GUI 系 §3 铁律）。**真值唯一在 core、前端不存**（`face_map`／`face_index` 一律不下发）。两处签名变更与数据类登记**均属实现会话请指挥方回填 §3 的报备项**（其件 docstring 已声明「本件不擅改文档」），指挥方于 T06 合并集成笔 `3e67ef3` 同轮处置 |
| kinematics/ | 正解 | `fk(joint_values:dict[str,float], model:KinematicModel)->dict[str,Transform4x4]` 每部件位姿（**行主序** 16 元素，均在**设备坐标系**内，要上屏再经 `device_to_scene`）；`model` 由 `build_model(cfg:MachineConfig, joints:Sequence[Joint])->KinematicModel` 一次解析后**复用**（实测 `build_model` 9.5 µs、`fk` 189.2 µs／13 节链 ⇒ ⛔ 禁在 T07／T08 的循环里重建拓扑） |
| kinematics/ | 逆解 | `ik(target_pose:Transform4x4, chain:Chain, seed:dict[str,float]|None=None)->dict[str,float]`（**解析闭式解，禁数值迭代**；桁架移动副解位置、腕部回转副解姿态，二者解耦；多解按行程/连续性选解，`seed` 给定则按连续性选支；契约 §5.2 下发关节空间目标即靠它）✅ **2026-09-17 T07 交付后回填本行**：链拓扑由 `derive_chain(cfg:MachineConfig, end_link:str|None=None)->Chain` 从配置（G18 扩的 `links.axis`／`links.motion`）一次解析、`tool_link(cfg)->str` 取工具连杆名；`Chain` 字段＝`model／path／end_link／effective_end`。⛔ **0 硬编码轴 id、⛔ 无数值迭代**（`ik.py` 内 `while` 仅为父链有界遍历、`_POSE_TOL=1e-9` 是位姿比对容差非收敛判据）；内部一律**行主序**，不可达抛 `IkError`（带原因句）。指挥方独立往返复测：自造合成链手算精确命中、`fk∘ik` 偏差 `0.0`、不可达→`IkError` |
| kinematics/ | 校核 | `check_limits(joint_values, cfg:MachineConfig)->list[Violation]`（行程／限位**＋龙门双驱 sync 偏差**，一次返回全部不通过项；行程／容差／倍率**全取自配置**，T07／T08 的「禁发」判据以返回**空表**为准） |

  - ⚠️ **`master` 自指的判读口径（2026-09-16 定案，随 T03 交付）**：`machine.yaml` 实测为 `{type: ratio, master: X3, ratio: 2.0}`——**master 指向自身**，因为倍速链的主动件（二级筒／伸缩油缸）**不是** 22 轴清单里的受控轴，无第二根轴可指。故判读规则为：**`master == 自身` ⇒ 驱动级倍速**，即「该轴工程位置 = 自身驱动位移 × ratio」；⛔ **禁**读成「X3 = 另一根轴 × 2」的**跨轴约束**。只有 `master != 自身` 时才按跨轴口径（从动轴 = 主动轴 × ratio）。**凡用 fk 的单（T04 正解／T07 逆解与段生成／T08 碰撞校核）都须先判这一支**；ratio 换算必须配置驱动，禁在代码里写死 `* 2`。终局依据＝踏勘确认清单第 4 项回执（软件下发三级筒实际位置，还是由 PLC 按下发值换算），回执后**只改 `machine.yaml`、不改码**。
- 行程/零点/正方向以电气·机械回执为准；回执前样例逐轴标 `pending: true` 占位，加载器对占位**告警不拒绝**。
- **职责边界（2026-09-15 22:43 @user 明确）**：**主要动作由 PLC 编程**；**涉及轨迹编程的工况，由软件输出轨迹参数**（当前工作模式轨迹级轴的段序列：目标位置／速度／过渡方式）交 PLC 执行。软件**不输出整机运动程序**；PLC 负责把轨迹参数接入其主程序（启动条件、与工序动作的衔接、异常中止均由 PLC 侧程序负责）。
