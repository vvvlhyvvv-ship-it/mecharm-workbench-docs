# 架构设计：几何内核 + Web 显示层 V1.0

- 编制：工程智拓 @pm ｜ 2026-09-14 ｜ 依据：01 需求 D-3、开发规程 §4/§5（S-2 POC、S-4 顺序）、S-1 契约
- 读者：ZCode 照此建骨架；@user 只需看 §1 结论表

## 1. 为什么是这套架构（结论先行）

四项硬要求：①桌面工控机交付 ②真几何不能只渲染面片（16(2)）③≥10Hz 轴联动 ④碰撞必须几何级判定。

| 候选 | 判 | 原因 |
|---|---|---|
| 纯浏览器栈（three.js + WASM） | ✗ | 工控机离线部署弱、非桌面交付形态、WASM 几何能力浅 |
| PyQt+PyOpenGL 自绘 | ✗ | 渲染底座从零造，成本高效果差 |
| Qt3D | ✗ | 生态萎缩，显示网格管线不成熟 |
| 收费 SDK（HOOPS/Hosm） | ✗ 本期 | 许可成本未询价，违反 D-8 |
| **OCC 内核 + PySide6 外壳 + 内嵌 Web 视图（本地桥传显示网格）** | ✅ | 真 B-Rep 校验+成熟渲染底座+团队 Python 栈 |

## 2. 进程与数据流

```
┌─────────────────────────────────────────────────┐
│ PySide6 桌面外壳（工作台 UI：步骤条/树/列表/日志）  │
│   ├─ QWebEngineView ── 三维视口（three.js 渲染）   │
│   └─ QWebChannel ⇄ 本地 WS ── 双向桥（bridge.py） │
├─────────────────────────────────────────────────┤
│ core/（纯 Python，无 GUI 依赖，可单测）            │
│   config.py    参数体系（轴/行程/零点/比例/方向）   │
│   kinematics.py 串联移动副+回转副正解/解析逆解、坐标变换│
│   geometry.py  OCC 导入/装配树/B-Rep校验/tessellation│
│   collision.py 碰撞三态（OCC 精判，FCL 备选）      │
│   path.py      路径生成+行程/可达性校核            │
│   project.py   工程文件 JSON 读写（带版本号）      │
├─────────────────────────────────────────────────┤
│ comm/（独立于 core）                              │
│   opcua_client.py  asyncua 客户端，Subscription    │
│   simulator.py     按 S-1 点表自建 OPC UA Server   │
└─────────────────────────────────────────────────┘
```

- **单向数据流**：core 算 → 显示网格推给视口；视口只回传交互事件（拾取/视角）。禁止前端碰几何判定。
- **几何真身在 Python 侧**：拾取请求带 mesh_id+face_id+三角形重心坐标，core 换算回 B-Rep 面上的真实 3D 点与法向。

## 3. 模块职责与接口签名（骨架，ZCode 照签名填）

| 模块 | 关键函数 | 签名（定死） |
|---|---|---|
| geometry.py | 导入 | `import_model(path:str)->Assembly`（含 `is_brep:bool, tree:[AssemblyNode], stats:{parts,tris,load_ms}`） |
| geometry.py | 显示网格 | `tessellate(assembly, deflection:float)->list[MeshPart{id,name,vertices:nx3 float32,tris:nx3 uint32,face_map:nx1 int32}]`（face_map=三角形→B-Rep 面 ID 映射，T06 取真值法向的唯一依据） |
| kinematics.py | 正解 | `fk(joint_values:dict[str,float])->dict[str,Transform4x4]` 每部件位姿 |
| kinematics.py | 逆解 | `ik(target_pose:Transform4x4)->dict[str,float]`（**解析闭式解，禁数值迭代**；桁架移动副解位置、腕部回转副解姿态，二者解耦；多解按行程/连续性选解；契约 §5.2 下发关节空间目标即靠它） |
| kinematics.py | 校核 | `check_limits(joint_values)->list[Violation]`（行程/限位） |
| collision.py | 三态 | `check(path:list[Segment], clearance_warn_mm:float)->CollisionResult{verdict:'pass'|'warn'|'interfere', cases:[{seg_id,part_a,part_b,min_dist_mm,point}]}` |
| path.py | 生成 | `gen_path(points:list[Waypoint])->list[Segment]`（段类型 LINE/JOINT，含长度） |
| project.py | 工程 | `save/load(path)`，JSON schema 版本字段 `"$schema":"proj/v1"` |
| bridge.py | 桥消息 | JSON 协议见 §5 |
| opcua_client.py | 连接 | `connect(endpoint,cfg)->Session`；回读回调 `on_frames(list[Frame])`，Frame=时间戳+各轴工程值 |

**铁律**：core 不得 import PySide6/asyncio 之外的 GUI/通讯包；comm 不得 import 三维显示；一切跨界走 bridge 消息。

## 4. 参数体系（配置文件，先于业务逻辑——规程 §4.1）

`config/machine.yaml` 字段（T02 实现加载与校验）：

```
machine: {name, schema_ver}
axes:    [{id, type: prismatic|revolute, travel:[min,max], zero_offset_mm|deg,
           direction: 1|-1, scale: mm_per_pulse|deg_per_pulse 或 null(已是工程值),
           coupling: null|{group, sync_tol_mm}}]      # 龙门双驱=轴耦合项
links:   [{id, length_mm, parent}]                    # 连杆几何参数
limits:  {speed_max_mm_s, speed_rapid_mm_s, speed_work_mm_s, accel_max_mm_s2,
          clearance_warn_mm, path_sample_step_mm}   # rapid=空程/work=作业(T07)；采样步长(T08)
opcua:   {endpoint_url, security_policy, ns_index,
          read_nodes: {axis_pos: [NodeId...], status: NodeId, heartbeat: NodeId},
          write_nodes: {cmd: NodeId, seg_count: NodeId, seg_array: NodeId},
          publish_interval_ms: 50}
```

- 界面任何地方**不许出现魔法数字**；加载时校验必填字段，缺项拒绝启动并列明细。
- ⚠️ `opcua:` 节点表 = 按 S-1 契约 §4/§5 自建（模拟期）；电气方 Q 回执冻结后只改此文件不改代码（D-6）。

## 5. 桥消息协议（JSON，bridge.py ⇄ view/js，全 ASCII）

| 方向 | type | 载荷 |
|---|---|---|
| 壳→视口 | `mesh.load` | MeshPart 数组（顶点/索引 base64 Float32/Uint32） |
| 壳→视口 | `pose.update` | {joint_values 或每部件 4x4 扁平矩阵, ts} |
| 壳→视口 | `path.show` | 段数组；`pick.enable` 开关拾取模式 |
| 壳→视口 | `hl.set` | 高亮部件列表+颜色语义(ok/warn/deny) |
| 视口→壳 | `pick.face` | {mesh_id,face_id,u,v}（壳侧换真实点/法向） |
| 视口→壳 | `cam.view` | 视角变化（仅日志用，可后置） |

- 轴动高频通道：`pose.update` 直发关节值，视口端用与 core 同一份 links 参数做正解插值（线性插值到 60fps，**禁止外推预测**——规程 W-5.7）。
- **大模型传输预案**：`mesh.load` 按 MeshPart 分批推送；20MB 级模型若 JSON+base64 经 QWebChannel 吞吐不足（T05 实测耗时为准），降级为本地临时文件+路径传递或二进制通道——先实测再定，不许拍脑袋优化。
