## 三、可复用纪律（**已沉淀进技能 `parallel-task-dispatch` v1.4.0**，跨项目通用）

| # | 纪律 | 技能条目 |
|---|---|---|
| 1 | **报数三件套**：数字 ＋ 口径 ＋ 来源；分不清就标【估】 | §9-3 |
| 2 | **探测失败 ≠ 事实不存在（假否定）**；只有现象没有机制时，**写"机制未确认"，不补归因** | §9-10、§9-16 |
| 3 | **命令成功但落在意料之外的同名程序上，同样不构成证据**（裸 `sort`／`find`） | §9-10、§9-16 |
| 4 | **环境事实分两层**：机器级（PATH 基础/系统代理）＋ **会话级**（会话 PATH／环境变量代理）——"在我机器上通过"只对**该会话**成立 | §9-16 |
| 5 | **"开发机能下载" ≠ "离线能跑"**：离线要求（禁 CDN、本地 vendor）必须在**断网／禁代理**下验证 | §9-16 |
| 6 | **规范写在指挥方文档里 ≠ 执行层已合规**：定稿后必须回头扫 `Tasks\` 单与派单卡（会话最先读、往往也只读它们） | §9-15 |
| 7 | **"未改动／零改动"是高风险声明**：必须先脚本逐字符比对再写，并降级为可验证口径 | §9-13 |
| 8 | **两套编号相同、含义不同**：有**两条独立危害路径**——查错表（靠带体系名解决）与**回填错行（改编号修不了，只能让答复自带原题）** | §9-11、§9-12 |
| 9 | **脚本批量改中文文档前先测引号风格**；长文本一律**三引号**；写入前断言"原串命中 = 1"；**同文件多处改动内存改完一次写回**；**文档里给的命令要原样提取实测** | §9-14、§9-17 |
| 10 | **拆包／改架构口径必须拍板**；且**别把收益讲高**（只消灭冲突、不消灭依赖） | §9-9 |
| 11 | **「阈值＝被测量的真值」时，通过线必须带量具分辨率容差**：凡判据形如「实测频率 ≥ 20 Hz」而真值恰为 20.000…，量具自身的有限窗口与推送抖动会让实测在阈值上下**随机翻面** ⇒ 通过线取「阈值 − 量具分辨率」。⚠️ **但容差的推导数字必须与实测散布对得上**（写"散布的 5 倍"而实测只有 2 倍，会让余量被高估）；⛔ **容差也不得大到把缺陷一起放过去**——必须配**负控**证明同一判据在反面条件下**会红**（本轮：`publish_interval_ms` 50→60 → 斜率 16.6642 Hz／FAIL／rc=1，差 3.3 Hz ⇒ 容差 0.01 无碍） | ⛔ **尚未进技能**（2026-09-16 T09 轮新增，待下一次 `parallel-task-dispatch` 升版收编） |
| 12 | **判据分层：自动化测试管"相对／一致性"，手动工具管"绝对量"——但绝对判据必须在 CI 侧留一条等价守卫**：把绝对阈值（≥20 Hz、<5 s）只放进**手动工具**，CI 就守不住它：**配置被静默改坏时 pytest 仍全绿**（实测 `publish_interval_ms` 50→60 → 手动工具会红、pytest 不会）。⇒ 凡"只活在手动工具里"的绝对判据，**须在 CI 侧补一条配置值守卫**（如断言 `1000 / publish_interval_ms >= 20`），使它**可红** | ⛔ **尚未进技能**（2026-09-16 T09 轮新增，同上） |
| 13 | **截取第三方实例内部对象（相机／场景）时，别包裹"构造期赋成自有闭包"的方法**：T06 要拿到 three.js 渲染器内部创建的相机与场景，最初想包裹 `WebGLRenderer.prototype.render`——**永不触发**：实例的 `render` 是构造期赋的**自有闭包**（own property），它**遮蔽**了原型方法，原型包裹根本不被调用。⇒ 改包裹**实例确实会走到的原型方法**：`THREE.Object3D.prototype.lookAt`（每帧被相机调用 → 截到相机）＋`THREE.Object3D.prototype.add`（截到场景＝`group.parent`）。**通用形态**：要 spy 一个对象，先确认目标方法是**原型方法**还是**实例自有属性**——自有属性（构造期 `this.fn = () => …`）必须在**实例创建后**直接替换该实例属性，原型层包裹一律无效（与 Python 侧 monkeypatch 的**模块遮蔽陷阱**同族：绑错层级 → 静默无效 → 假阴性） | ⛔ **尚未进技能**（2026-09-16 T06 轮新增，待下一次 `parallel-task-dispatch` 升版收编） |
