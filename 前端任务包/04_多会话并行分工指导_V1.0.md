### 4.5 代码粒度与质量硬约束（**全仓硬约束 · 每单必守**）

> **依据**：@user 2026-09-15 指令——"保证代码质量精简，行数不要过多，最好不要超过 300 行，可以多分几个代码文件"。
> **性质**：本约束**不改任何接口签名、不改任何完成标准、不增删任何任务**，只约束"一行代码落在哪个文件、一个文件装多少"。与 03 架构 §3 的接口签名要求**并行有效**；本约束与 §4 文件归属矩阵共同决定"谁能建哪个文件"。
> **谁执行**：ZCode 在每单内自测时自查并贴输出；指挥方收单时**复核**（§5.5-附4）。

#### ① 两条硬指标

| 指标 | 限值 | 量法（口径写死，避免扯皮） |
|---|---|---|
| **单文件** | **≤ 300 行** | **物理行数**（`wc -l`），**含空行与注释**。`.py` / `.js` / `.html` / `.css` 全部适用 |
| **单函数／方法** | **≤ 50 行** | 从 `def`/`function` 行到同缩进的下一个定义；超了说明该抽函数了 |

#### ② 超限时的正确处理顺序（**依次做，做完还不够才拆文件**）

1. **去重复**：同一段计算/同一段 DOM 操作出现两次以上 → 抽成一个函数；
2. **抽函数**：一个函数干了不止一件事 → 拆成两个；
3. **拆文件**：按职责把文件拆开；**新增的源文件名必须先报备**（见下"报备规则"），不许开工中途自行新建。

**报备规则**：新增源文件的三件事须先写进该单派单卡——**文件名 / 职责一句话 / 归属单**。跨单共享的文件（`app/panel.py`、`view/index.html`、`app/bridge.py`、`tests/conftest.py`）**只能由归属单拆**，其他单不得拆、不得重命名。

#### ③ 拆分准则（**按职责切，不按行数切**）

| 层 | 怎么拆 | 示例（示意，实际以派单卡报备为准） |
|---|---|---|
| `core/` | 一个文件一个职责域；超限优先"包 + 子模块"，**`__init__.py` re-export 保持原 import 路径不变** | `core/kinematics.py` 超限 → `core/kinematics/{__init__,fk,transform,limits,ik}.py`，`from core.kinematics import fk` 调用方零改动 |
| `app/` | 一个界面区域 / 一个步骤一个文件 | `app/panel.py` 装不下 5 步 → `app/steps/step1_import.py` … |

#### ⑤ 反作弊条款（**违反即打回**）

- **300 行是上限，不是目标**：不许为了"达标"做反可读性压缩——禁一行多语句（`a=1; b=2`）、禁把多个类/函数挤一行、**单行超过 120 字符要换行**。

## 5. 多会话并行操作规程

### 5.1 隔离机制：git worktree + 每单分支（唯一合规做法）

**为什么必须这么做**：00_README 铁律"同一仓同一时刻只进一单，**避免工作树打架**"。多会话若共用同一工作树，必然打架；用 worktree 把工作树**物理分开**，每个会话在自己的目录里改自己的文件，就同时满足"另开会话另派单"与"不打架"。

cd /d/ZCode项目/多功能机械臂软件
# ⓪ ⚠️ **建之前先确认 main 上没有未提交的任务包文档改动**（2026-09-16 02:29 实测教训，见硬规矩 7）：
#    git status --porcelain -- 前端任务包 参考资料     # 期望：空
#    原因：`git worktree add` 从 **HEAD 提交**检出，**不看 main 的工作树** → 未提交的卡片改动
#    不会进 worktree，实现会话读到的是**旧派单卡＝旧判据**。实测：HEAD 版 `Tasks\T02` 卡

1. **一个 worktree 只跑一单**，一单一个分支 `task/TXX`，一次 commit（格式 `feat(TXX): <一句话>`，T01 用 `chore(T01)`）。
   - ⚠️ **T01 例外（2026-09-16 @user 追认）**：T01 实为 **2 个 commit**——`chore(T01): 环境基线` ＋ `chore(T01): 遗留问题处置——ICU 入口引导抽出共用＋vendor 换行保真`。理由：遗留处置发生在**收口汇报之后**，与环境基线是**两件独立事实**；**不改写历史去 squash**（squash 会重写已复核的基线提交，并抹掉"遗留处置"这条留痕）。**T02 起仍按"一单一次 commit"**；若某单确需追加"遗留处置"类提交，照此例**在汇报里写明理由，由指挥方收单时认定**，不自行扩例。

4. worktree 必须**在仓外同级目录**（`多功能机械臂软件-wt/`），不许放进仓内，否则会被 git 跟踪。

### 5.5 常驻复查三项（每单必查，99 原文）＋可用命令

> ⚠️ **Bash 命令可用性随会话变化（不是本机固定事实；2026-09-15 双方各自实测）**：同一条 `grep`／`awk`／`wc`／`ls`，**不同会话可能一好一坏**——
> - 某会话（WorkBuddy 侧 Bash，PortableGit shim）：PATH **不含** `/usr/bin`、不含 `/mingw64/bin`（只有 `/Git/cmd`）→ `ls`／`grep`／`awk`／`wc`／`sed` 全报 `command not found`；**且裸 `sort`／`find` 会静默解析到 `C:\Windows\system32\sort.exe`／`find.exe`**（**语义不同却不报错**：`find` 是文本查找、`sort` 排序规则不同）。
> - 另一会话（@user 终端）：`/usr/bin` 下 `ls`／`grep`／`awk`／`wc`／`sort`／`find` **全部正常解析**，`git` 在 `/mingw64/bin`。
