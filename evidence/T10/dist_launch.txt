== 1. 启动方式（§7 报数项⑧要求说明） ==
包位置（干净副本，与仓内 dist/ 同构）：D:\t10_dist_clean\mecharm\
启动命令（PowerShell，模拟「工控机没装 Python」）：

    $env:PATH = 'C:\Windows\System32;C:\Windows'      # 剥掉一切 Python/conda 路径
    Remove-Item Env:QTWEBENGINE_CHROMIUM_FLAGS -ErrorAction SilentlyContinue   # 不设任何外部 Chromium 旗标
    Start-Process -FilePath 'D:\t10_dist_clean\mecharm\mecharm.exe' -WorkingDirectory 'D:\t10_dist_clean\mecharm'

即：**直接双击／Start-Process 该 exe 即可**，无需任何环境变量、无需 Python、无需 conda。
（`run.py` 在冻结态自己 `os.environ.setdefault("QTWEBENGINE_CHROMIUM_FLAGS", "--single-process")`，
见下 §3；用户若自行设了该变量则以用户值优先，setdefault 不覆盖。）

== 2. 多进程渲染崩溃的对照证据（为什么需要 §3 的旗标） ==
同一份包、同一干净目录，**外部强设** QTWEBENGINE_CHROMIUM_FLAGS='--enable-logging=stderr --v=0'
（该外部值使 run.py 的 setdefault 不生效 ⇒ 走默认多进程）时，stderr 抓到渲染子进程连死两次：

    [26224:23316:0917/171601.114:...web_contents_delegate_qt.cpp:299] ProcessGone: 3 (-1073741511)
    [26224:23316:0917/171601.224:...web_contents_delegate_qt.cpp:299] ProcessGone: 3 (-1073741511)

-1073741511 = 0xC0000139 = STATUS_ENTRYPOINT_NOT_FOUND（渲染子进程加载某 dll 缺导出即死）。
界面表现为视口错误卡「三维视口加载失败 / 无法加载视口页面：…\_internal\view\index.html」
（文件其实存在，是渲染进程死了，不是缺文件）。
排查过程（ICU／VC 运行时大小写重复／OpenGL 软件兜底 opengl32sw／sandbox／GPU 进程／
RendererCodeIntegrity 逐一排除，均不能消除该崩溃）详见本单汇报正文；根因未定位到单一 dll，
属本 conda-Qt 构建在 onedir 冻结态的固有行为。

== 3. 交付口径：冻结态单进程 WebEngine ==
`run.py`（唯一入口）在 `getattr(sys, "frozen", False)` 时 setdefault 追加 `--single-process`。
开发态（python run.py）与 e2e 冒烟（不 frozen）不受影响，仍走默认多进程。
该旗标下 stderr 仅余两条**无害**提示（V8 Proxy resolver 在单进程模式不可用，与功能无关）：

    [25872:21808:0917/171707.968:...system_network_context_manager.cpp:325] Cannot use V8 Proxy resolver in single process mode.
    [25872:21808:0917/171707.975:...system_network_context_manager.cpp:325] Cannot use V8 Proxy resolver in single process mode.

ProcessGone 计数 = 0（`grep -c ProcessGone dist_stderr2.txt` → 0）。
